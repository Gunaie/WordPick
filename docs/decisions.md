## D19 · 用目录连接（Junction）替代符号链接，绕开开发者模式

| 项 | 内容 |
|---|---|
| 日期 | 2026-11-03 |
| 背景 | Flutter 在 Windows 上为插件创建**符号链接**，该操作需要开发者模式或管理员权限；本机两者都不具备 |

| 自动化 | `scripts/fix_plugin_links.ps1` 读取 `.flutter-plugins-dependencies` 自动为所有 Windows 插件建 Junction（纯 ASCII，避免 PS 5.1 中文编码问题） |
| 持久性 | `flutter pub get` 后 Junction 不会被清除（已实测） |
| 限制 | 新增 Windows 插件后需重跑该脚本；仅解决 Windows 桌面，不影响其他平台 |
| 状态 | ✅ 已定（无需开发者模式） |

## D21 · 环境为 PostgreSQL 模式，权限用 GRANT 授权

| 项 | 内容 |
|---|---|
| 日期 | 2026-11-03 |
| 事实 | 该环境是 **PG 模式**（实例 `postgres-nb27zage`），没有文档数据库；写文档会报 `DATABASE_COLLECTION_NOT_EXIST` |
| 权限模型 | 表级 `GRANT` + 行级 `RLS` 双层。客户端 Publishable Key 对应 `anon` 角色 |
| 关键坑 | 建表后 `anon` **默认可读不可写**，写入报 `DATABASE_42501 permission denied` |
| 解决 | 执行 `grant select, insert, update, delete on table ... to anon;` |
| 编辑器误报 | SQL 编辑器会提示"检测到 Supabase 内置角色 anon" —— **误报**，CloudBase PG 模式官方就是这三个角色 |
| 实测 | anon：INSERT 201 / SELECT 200 / DELETE 204 ✅ |
| 状态 | ✅ 已定 |

## D24 · 词根词缀：自建知识库 + 保守匹配，不依赖词源数据库

| 项 | 内容 |
|---|---|
| 日期 | 2026-11-03 |
| 背景 | 内置词书的 `rel` 字段是"同根词"，不是词缀拆解；做「词根词缀」需要独立的词缀知识 |
| 决策 | ① 自建 `assets/data/affixes.json`（30 前缀 / 30 词根 / 24 后缀，共 84 条），标注含义与示例词；② 拆解算法用**保守规则**：词缀长度 ≥ 2、剩余部分 ≥ 3 字母、同类型只保留最长命中；③ **2 字母后缀必须有词典佐证**（去掉后缀后是已知单词）才展示 |
| 为什么保守 | 宁可少拆，也不要把 `in`、`a` 这类误当词缀，误导学习者 |
| 修正记录 | 实机发现 `abdomen`（腹部）被误拆成 `-en 动词`。加入"词干必须是已知单词"校验后：abdomen → 不拆；strengthen → 拆（stem=strength 在词库中） |
| 覆盖面 | 收录的是学界通用、无争议的构词成分；不做生僻词源考据 |
| 验证 | 14 个单测通过（含 predict → pre- + dict、inspection → 前缀/词根/后缀、短词不拆、最长优先） |
| 已知限制 | 搜索会同时匹配"词形/含义/示例词"，所以搜 `dict` 也会命中 `pre-`（示例词含 predict）——属预期行为 |
| 状态 | ✅ 已实现 |

## D26 · 清空数据：本机与云端一起清，不做"只清本机"

| 项 | 内容 |
|---|---|
| 日期 | 2026-11-03 |
| 背景 | 换设备或重新开始时需要重置；此前测试数据（`predict`）也需清理 |
| 决策 | 只提供一个动作「清空全部数据」，同时清本机与云端 |
| 为什么不给"仅清本机" | 清完本机后，下次同步会立刻把云端数据拉回来，用户会以为没生效——这是陷阱，不做 |
| 实现 | `store.clearAll()` 清本地四类数据；`CloudSync.wipeAll()` 对三张表发 `DELETE ... ?user_id=eq.me` |
| 失败处理 | 若云端清空失败，提示「本机已清空，但云端清空失败：…」，不谎报成功 |
| 确认机制 | 二次确认弹窗，红色按钮，列出将被删除的 5 类数据 |
| 验证 | 浏览器实测：已学 3 → 0，SnackBar 提示；云端三表 `rows=0` |
| 状态 | ✅ 已实现 |
