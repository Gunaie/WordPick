### 2.6 四六级 / 考研专项设计

#### 考纲词表覆盖

| 考试 | 官方词量 | 处理方式 | 特殊处理 |
|---|---|---|---|
| CET-4 | 4500 | 导入教育部考试中心词表 | 标注"CET-4 核心 2000 / 扩展 2500" |
| CET-6 | 6000 | 导入教育部考试中心词表 | 标注"CET-4 已覆盖 / CET-6 新增" |
| 考研英语 | 5500 | 导入教育部考试中心词表 | 区分"英语一 / 英语二"差异词 |

#### 题型考频分布方案

```sql
-- 基于历年真题语料库做的题型词频统计
-- 2018-2026 CET-4/6 + 2018-2026 考研英语 共约 100+ 套真题
exam_word_freqs 表:
  word_id         TEXT FK → words
  exam_type       TEXT     -- 'cet4' / 'cet6' / 'kaoyan'
  section_type    TEXT     -- 'reading' / 'listening' / 'writing' / 'translation' / 'cloze'
  freq_count      INTEGER  -- 出现次数
  freq_rank       INTEGER  -- 在该题型中的排名
  total_words_in_section INTEGER
```

**核心价值**：同一个词 "render"，在考研阅读里出现 12 次但写作里 0 次 → 告诉用户"这个词你认识就行，不用会写"。反过来 "significant" 写作高频 → 告诉用户"这个词要会拼写"。

#### 长难句拆解方案（v2.3）

```
输入：考研真题阅读中的长难句
输出结构：
{
  "sentence": "The notion that learning should have in it an element of inspired play would seem to the greater part of the academic establishment merely silly...",
  "breakdown": {
    "main_clause": { "text": "The notion ... would seem ... merely silly", "keywords": ["notion", "seem", "silly"] },
    "clauses": [
      { "type": "appositive", "text": "that learning should have in it an element of inspired play" },
      { "type": "prepositional", "text": "to the greater part of the academic establishment" }
    ]
  },
  "grammar_points": ["同位语从句", "介词短语作状语"],
  "difficulty_score": 8.5,   // 1-10
  "exam_source": "kaoyan-2023-reading1-para2-sentence3"
}
```

**实现方式**：用 Stanford CoreNLP 或 spaCy 做句法分析 + 人工校对（第一版先收集 500 句考研长难句手动拆解）。

## 3. 技术架构

### 3.1 选型结论

| 层级 | 技术 | 理由 |
|---|---|---|
| **客户端框架** | Flutter 3.x | 一套代码覆盖 Android/iOS/Windows/macOS/Web；UI 一致性 100%；性能优于 RN |
| **本地存储** | SQLite（drift 包） | 离线优先；drift 提供类型安全的 DAO；支持增量迁移 |
| **云端存储** | Supabase | PostgreSQL + Realtime + Auth + Storage 一体化；免费额度（500MB 数据库 + 1GB 存储）够个人用；有 Flutter SDK |
| **后端** | Supabase（无自建） | MVP 阶段不写后端；用 Supabase 的 Row Level Security 做权限；后续需定制逻辑再上 Edge Functions |
| **同步机制** | Supabase Realtime + 本地版本戳 | 云端为 Source of Truth；每条记录带 `updated_at`；冲突策略：后写入者胜 |
| **词典/发音** | Free Dictionary API + Forvo（备份） | 免费无 Key；覆盖英美双发音；Wiktionary 授权数据 |

### 3.3 同步策略

```
写入流程：
Client → SQLite (本地写入，状态: pending)
       → Supabase (写入云端，状态: synced)
       → 失败重试（指数退避，最多5次）

读取流程：
1. 优先读本地 SQLite（毫秒级响应）
2. 后台检查云端是否有更新（按 updated_at 比较）
3. 有更新 → 拉取并覆盖本地

冲突解决：
- 每条记录带 updated_at + version
- 冲突时取 updated_at 更新者（Last-Writer-Wins）
- 用户自建内容由用户自己创建，不存在多人协作冲突
```

## 7. 间隔重复算法选型

### 7.1 SM-2（v1.0 采用）

```
// Dart 实现核心逻辑
SRSResult schedule(UserWord word, Quality quality) {
  // Quality: 0=重来 1=难 2=一般 3=简单
  
  int repetitions = word.repetitions;
  double easeFactor = word.easeFactor; // 初始 2.5
  int interval = word.interval;
  
  if (quality.index < 2) {
    // 忘记了，重置
    repetitions = 0;
    interval = 1;
  } else {
    repetitions++;
    if (repetitions == 1) interval = 1;
    else if (repetitions == 2) interval = 3;
    else interval = (interval * easeFactor).round();
  }
  
  // 调整 E-Factor
  easeFactor = max(1.3, easeFactor 
    + (0.1 - (3 - quality.index) * (0.08 + (3 - quality.index) * 0.02)));
  
  return SRSResult(
    nextReview: DateTime.now().add(Days(interval)),
    interval: interval,
    easeFactor: easeFactor,
    repetitions: repetitions,
  );
}
```

**优点**：成熟、简单、经过 20 年验证
**缺点**：E-Factor 调整较粗，不考虑历史复习记录

### 7.2 FSRS-5（v2.0 升级备选）

```
// FSRS 核心公式（简化版）
// R(t, S) = exp(-ln(9) * t / S)
// D' = D + w_D * (1 - (delta - 1)^2 / ((1 - C)^2))
// S' = S * exp(w_F * (delta - 1))
```

**优点**：更精准、考虑更多变量、开源实现已有
**缺点**：参数调优需要用户数据积累，实现复杂度略高

**决策**：v1.0 上 SM-2 快速出活；有 3 个月以上用户数据后再上 FSRS。

## 9. 风险与缓解策略

| 风险 | 概率 | 影响 | 缓解策略 |
|---|---|---|---|
| Free Dictionary API 不稳定 | 中 | 高 | 接入有道/Forvo 作为 fallback；关键数据预加载缓存到本地 |
| Supabase 免费额度用完 | 低 | 中 | 自建 PostgreSQL 迁移；或接受小量付费（$25/月起） |
| 用户自建词库格式不统一 | 高 | 低 | CSV 模板强制；上传前做格式校验；提供格式错误提示 |
| 跨端同步冲突 | 中 | 中 | 简单 LWW 策略；不支持多人协作；冲突时以 `updated_at` 为准 |
| 版权问题（词典/例句） | 中 | 高 | Free Dictionary API 数据来自 Wiktionary（CC BY-SA）；商业词典不碰；真题例句标注来源 |
| 个人开发精力不足 | 高 | 高 | 严格限制 MVP 范围；砍功能比加功能难；4 周做不完再砍 |
| 音频文件体积 | 中 | 低 | 首次播放时下载，缓存到本地；LRU 淘汰 |
