## 1. 实测结论：已验证的事实

### 1.1 词典 API 实测对比

| 指标 | Free Dictionary API | 有道 dict.youdao.com |
|---|---|---|
| **单次请求耗时** | 1619 ms/词（10词串行） | **52-94 ms** |
| **音标** | 有（IPA） | **有 usphone + ukphone**（英美分开） |
| **英美双发音** | ❌ 经常只返回美式 | ✅ 明确分开（type=0美/type=1英） |
| **中文释义** | ❌ 只有英文 | ✅ **返回中文释义** |
| **例句** | 有 | 部分有（web_trans 字段） |
| **需要 API Key** | 否 | 否（但可能是内部接口） |
| **授权风险** | CC BY-SA 3.0（安全） | **灰色地带**（APP内部接口，可能变） |

**实测代码**（Node 24，国内网络）：
```javascript
// Free Dictionary: predict 1.6秒/词，只有美式音频
// 有道美音: 52ms, 有道英音: 94ms, 查词: 90ms
const r = await fetch('https://dict.youdao.com/jsonapi?dicts=ec.basic&q=predict');
// 返回: { usphone: "prɪˈdɪkt", ukphone: "prɪˈdɪkt", ukspeech: "predict&type=1", trs: ["v. 预言，预计"] }
```

### 1.2 发音音频实测

| 来源 | 英音 | 美音 | 音频大小 |
|---|---|---|---|
| `dict.youdao.com/dictvoice?type=1&audio=<word>` | ✅ 94ms | — | 10.7 KB |
| `dict.youdao.com/dictvoice?type=0&audio=<word>` | — | ✅ 52ms | 10.4 KB |
| `api.dictionaryapi.dev/.../phonetics[].audio` | ❌ 经常缺失 | ✅ 偶有 | 外部CDN |

**结论**：有道接口速度快 20 倍，且明确返回英美双音 + 中文释义。但这是灰色接口，需要 fallback。

### 1.3 本地存储实测验证

| 项 | 验证结果 |
|---|---|
| Flutter Windows 支持 | ✅ 稳定支持 Win10/11（官方 CI 测试） |
| drift (原 moor) SQLite Windows | ✅ 用 `path_provider` 存到 `getApplicationDocumentsDirectory()` |
| sqlite3_connection_pool | ✅ 支持 Windows，高并发连接池 |
| Flutter 桌面端插件生态 | ⚠️ 注意：部分 Android 专属插件 Windows 不支持 |

### 1.4 现成 Dart 包（不用自己造轮子）

| 包名 | 功能 | 适用场景 |
|---|---|---|
| `flutter_spaced_repetition` | SM-2 / SM-2+ 间隔重复 | 生产级，纯 Dart，支持所有平台 |
| `dart_srs` | **FSRS-6** 调度器 | 可插拔，存储无关，支持复习日志 |
| `spaced_repetition` | 简单 SM-2 | 44天前更新，简单场景 |

**决策**：v1.0 用 `flutter_spaced_repetition`（SM-2），v2.0 切 `dart_srs`（FSRS-6）。

## 2. 数据存储：最终方案

### 2.1 为什么放弃 Supabase

| 问题 | 影响 | 证据来源 |
|---|---|---|
| 国内延迟 200ms+ | 实时同步体验差，用户点了半天没反应 | YesApi 对比 + 腾讯云开发者社区 |
| 偶尔无法访问 | 用户在地铁里用着用着断了 | 多个开发者报告 |
| 免费额度缩水 | 2025年8月起 Firestore 读取从 5万/天 降到 2万/天 | Firebase Spark 档变更 |
| 数据境外存储 | 合规风险（虽然个人项目问题不大） | — |

### 2.2 最终选型：CloudBase（腾讯云开发）

| 指标 | Supabase | **CloudBase（最终选择）** |
|---|---|---|
| 国内延迟 | 200ms+ | **20-40ms** |
| Flutter SDK | ✅ supabase_flutter | ✅ **cloudbase_core 1.2.2**（支持 Android/iOS/Web/macOS/Linux/Windows 全平台） |
| 实时同步 | ✅ Realtime | ✅ **watch() 实时监听** |
| 关系型数据库 | ✅ Postgres | ✅ **Postgres（已上线）** |
| 文档型数据库 | ✅ | ✅（更适合用户学习数据） |
| 文件存储 | 500MB免费 + 5GB流量 | 3000资源点/月（免费兑换码，可续期6个月） |
| Auth | ✅ JWT + OAuth | ✅ 匿名登录 + 自定义 |
| 免费额度 | 2项目，500MB DB | **1免费环境，3000点/月**（需兑换码，2026新规则） |
| 合规性 | 境外 | **境内** |

### 2.3 CloudBase 免费额度换算（个人项目）

| 资源 | 消耗（估） | 3000资源点/月够用吗 |
|---|---|---|
| 数据库读操作 | 假设每人每天 1000 次 → 约 50 用户 | ✅ 够 |
| 数据库写操作 | 每人每天 200 次 | ✅ 够 |
| 云存储 | 音频 10KB/条 × 1000条 = 10MB | ✅ 够 |
| 云函数调用 | 每天 1000 次 | ✅ 够 |
| 带宽 | 音频 10MB × 30天 = 300MB | ✅ 够 |

**风险应对**：免费额度用完 → 按量付费（约 ¥10-30/月），或自建 Postgres + MinIO（全免费）。

└──────────────────────────────────────────────────────────┘

### 2.5 同步流程（最终版）

```
写入流程：
  App → drift SQLite（立即写入，状态=local）
      → CloudBase doc → 成功则状态=cloud
      → 失败（无网/慢）→ 放入 pending_sync 队列 → 后台重试（指数退避）

读取流程：
  1. 读 drift SQLite（毫秒级，离线可用）
  2. 后台对比 updated_at 版本号
  3. 云端更新 → 拉取 → 覆盖本地 → 触发 App 刷新

冲突解决：
  - 全部带 updated_at + version 字段
  - Last-Writer-Wins（后写覆盖）
  - 不支持多人协作（个人项目，简单可靠）

离线场景：
  - 完全可用（读本地 SQLite + 写本地待同步队列）
  - 联网后自动 resume
```

### 2.6 为什么静态数据打包进 APP

| 原因 | 说明 |
|---|---|
| **省流量** | 考纲词表约 5000+ 词 × 1KB ≈ 5MB，打包进 APK/EXE 零网络开销 |
| **快** | 打开 APP 不需要等云端加载词表 |
| **离线可用** | 地下/地铁也能背单词 |
| **省 CloudBase 资源点** | 静态数据不走云端，全部用本地 |

**更新策略**：每次发新版本时更新静态词表（每年 1-2 次，考纲变化很慢）。

## 3. 词典/发音 API：最终方案

### 3.1 三源组合策略

```
查询请求
   │
   ├── 第一源：有道 dict.youdao.com（主）
   │   ├── 发音：dictvoice?type=0/1&audio=<word> → 50-90ms
   │   └── 释义：jsonapi?dicts=ec.basic&q=<word> → 90ms
   │   ✅ 优点：快、有英美双音、有中文释义
   │   ⚠️ 风险：灰色接口（APP内部使用，可能随时变）
   │
   ├── 第二源：Free Dictionary API（fallback）
   │   ├── 发音 + 音标 + 英文释义
   │   ✅ 优点：官方、CC BY-SA 授权、稳定
   │   ❌ 缺点：慢（1.6s/词）、经常只有美式音频、无中文
   │
   └── 第三源：本地 TTS（兜底）
       └── 自建词库的单词 → 用 iOS AVFoundation / Android TTS / Flutter tts 包合成
       ✅ 100% 可用，但音质不如原生
```

### 3.2 接口熔断策略

```dart
class DictionaryService {
  static const _timeout = Duration(milliseconds: 500); // 500ms 超时

  Future<WordData> fetch(String word) async {
    // 1. 本地缓存命中 → 直接返回
    final cached = await _localCache.get(word);
    if (cached != null) return cached;

    // 2. 主源：有道（500ms 超时，避免卡住）
    try {
      final data = await _fetchYoudao(word).timeout(_timeout);
      if (data.isValid) { await _localCache.save(word, data); return data; }
    } catch (_) {} // 超时或失败 → 切 fallback

    // 3. Fallback：Free Dictionary
    try {
      final data = await _fetchFreeDict(word).timeout(_timeout);
      if (data.isValid) { await _localCache.save(word, data); return data; }
    } catch (_) {}

    // 4. 兜底：返回最简结构（只有单词拼写，没有音频）
    return WordData.fallback(word);
  }
}
```

### 3.3 有道接口返回结构（已实测）

```json

{
  "ec": {
    "word": [{

### 4.2 包选择理由

| 包 | 为什么选这个而不是那个 |
|---|---|
| **drift over sqflite** | 类型安全 DAO、代码生成、支持所有平台（含 Windows） |
| **cloudbase_core over supabase_flutter** | 国内快 5 倍，官方 Flutter SDK 支持 6 平台 |
| **cloudbase_core over firebase_core** | Firebase 2025 免费额度腰斩 + 国内同样慢 |
| **flutter_spaced_repetition over sm2** | 生产级、纯 Dart、无外部依赖、可调参数 |
| **dio over http** | 自动重试、取消请求、拦截器，调用有道/FD 更稳 |
| **excel over file_picker + 手动解析** | 纯 Dart 实现，各平台无需原生依赖 |
| **audioplayers over just_audio** | 更轻量，发音文件只有 10KB 不需要复杂播放器 |

## 5. 关键技术坑清单（避坑用）

### 坑 1：Free Dictionary API 国内太慢 🚨

| 现状 | 实测 1.6s/词，10 词串行 16s |
|---|---|
| 解决方案 | 有道主源（90ms）+ FD fallback + 本地缓存 |
| 优先级 | **P0 必须解决** |

### 坑 2：Supabase/Firebase 国内延迟高 🚨

| 现状 | 200ms+，实时同步卡顿 |
|---|---|
| 解决方案 | CloudBase（腾讯云，国内 20-40ms） |
| 优先级 | **P0 必须解决** |

### 坑 3：drift 在 Windows 上的数据库路径

| 问题 | Windows 上默认存到 `C:\Users\<user>\AppData\Roaming\<app_name>\databases\` |
|---|---|
| 风险 | 用户卸载 APP 后数据保留（不是坑，但要知道） |
| 代码 | `DriftNativeOptions(databasePath: customPath)` 可选自定义 |

### 坑 4：有道接口的稳定性

| 风险 | 内部接口，网易可能封 |
|---|---|
| 缓解 | `dio` 加超时 + 熔断机制（500ms 超时自动切 FD）+ 本地缓存 |
| 长期 | 接入有道智云 AI 开放平台的正式 API（付费但便宜） |

### 坑 5：CloudBase 免费额度 2026 年缩水

| 现状 | 从永久免费变成"3000资源点/月 + 一次性兑换码 + 6个月续期" |
|---|---|
| 缓解 | 静态数据打包进 APP（省资源点）+ 到期前导出数据 → 换免费环境 |
| 备份 | 自建 Postgres + MinIO（Docker 一台小机器全搞定） |

### 坑 6：发音音频 URL 里有 `&type=` 参数

| 问题 | 有道 `usspeech` 字段是 `"predict&type=2"` 不是完整 URL |
|---|---|
| 正确拼接 | `http://dict.youdao.com/dictvoice?type=0&audio=predict`（参数顺序要对） |

### 坑 7：自建词库的发音

| 问题 | 用户上传的单词，有道/FD 都查不到（如专业术语、缩写） |
|---|---|
| 解决 | `flutter_tts` 包调用系统 TTS 合成。iOS/Android/Windows/macOS 全部原生支持 |

### 坑 8：Windows 上部分插件不支持

| 例子 | `shared_preferences` ✅ | `path_provider` ✅ | `connectivity_plus` ✅ |
|---|---|---|---|
| 检查方法 | pub.dev 搜索插件 → 看 Platform 标签是否标了 Windows |
| 策略 | 选插件时**必须看 Platform 支持**，不支持的换替代方案或自己实现 |

### 坑 9：ESM / CJS 混用（集成开发环境）

| 问题 | 集成代码运行时默认 ESM（无 require），Node 24 默认 ESM |
|---|---|
| 解决 | 写 ESM 兼容代码：用 `import()` 动态加载 |

### 坑 10：Static Word Data 版本管理

| 问题 | 打包进 APP 的词表数据，发新版本前怎么更新？ |
|---|---|
| 方案 | 写一个 `scripts/word_sync.dart` 脚本：\n  1. 从有道批量抓词（5000词）\n  2. 合并词根词缀/考频数据\n  3. 输出 `assets/data/words.json` + drift 迁移 SQL\n  4. 跑脚本 → 自动生成 |

## 附录 A：CloudBase 免费额度注册流程

```
1. 打开 https://cloudbase.net/
2. 用微信扫码登录（或腾讯云账号）
3. 首页 → "领取免费额度" → 拿兑换码
4. 创建免费体验环境（选离你最近的区域：广州/上海/北京）
5. 环境创建后 → 拿到 envId
6. 在 Flutter 里:
   await CloudBaseCore.init({
     'env': 'your-env-id',
   });
